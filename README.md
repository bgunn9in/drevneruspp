# Древнерусъ++

Шуточный набор заголовков, позволяющий писать компилируемый C++17 так, будто
исходник составлял летописец при княжеском дворе:

```cpp
#include "drevnerus_stl.hpp"

цело главныйъ()
начати
    векторъ<цело> числа = {1, 2, 3};
    числа.добавити(4);

    длявсякаго (само число : числа)
    начати
        аще (число % 2 равно 0)
        начати
            глаголи число << " — число честное и чётное"
                    << конецстроки;
        окончати
    окончати

    возврати 0;
окончати
```

## Что лежит в архиве

- `include/drevnerus.hpp` — ключевые слова, типы, контейнеры, умные указатели
  и ввод-вывод;
- `include/drevnerus_stl.hpp` — русские псевдонимы методов STL и алгоритмов;
- `include/drevnerus_undo.hpp` — снимает все макросы;
- `examples/` — шесть отдельных компилируемых примеров;
- `scripts/` — готовые сценарии сборки для Visual Studio, Ninja и Unix;
- `CMakeLists.txt` — каждый пример собирается отдельной программой и
  регистрируется как тест.

## Быстрый запуск в Visual Studio 2026

Самый простой путь — открыть корневую папку проекта в Visual Studio и выбрать
сборку CMake. Для сборки из командной строки запусти:

```bat
scripts\build_and_test_vs2026.bat
```

Если используешь MSVC с Ninja, сначала открой **Developer PowerShell for
Visual Studio 2026**, затем запусти:

```bat
scripts\build_and_test_ninja.bat
```

Сценарии включают C++17, UTF-8, строгий препроцессор и предупреждения `/W4`.
Для генератора `Visual Studio 18 2026` нужен CMake 4.2 или новее. Твой
CMake 4.3.0-rc2 это требование выполняет.

Если твоя версия CMake называет генератор Visual Studio иначе, можно не
указывать его вручную:

```bat
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

## Linux и macOS

```sh
chmod +x scripts/build_and_test_unix.sh
./scripts/build_and_test_unix.sh
```

Либо обычными командами CMake:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## Смешные примеры

1. `01_bogatyrs.cpp` — собеседование богатырей с сортировкой по силе.
2. `02_koshchei.cpp` — бессмертие Кощея, реализованное через `shared_ptr`.
3. `03_marusya.cpp` — кошка Маруся принимает складские короба.
4. `04_potions.cpp` — лавка зелий, где зелье от дедлайна опять не завезли.
5. `05_bugtracker.cpp` — древнерусский баг-трекер.
6. `06_turnip.cpp` — безопасное деление репы без undefined behavior.

После сборки программы находятся в каталоге сборки. В конфигурации Visual
Studio это обычно `build-vs2026/Release/`.

## Важное предупреждение от волхвов

Это не новый язык и не настоящее переопределение ключевых слов. Стандарт C++
запрещает определять макрос с именем ключевого слова (`#define if ...`). Здесь
создаются разрешённые кириллические псевдонимы вроде `#define аще if`.

Макросы не понимают синтаксический контекст. Например, `количество` заменяется
на `size` везде, а не только после точки. Поэтому проект годится для шуток,
обучения препроцессору и устрашения коллег, но не для production-кода.

Если обычный C++ должен продолжаться ниже в том же `.cpp`, заверши древнерусский
участок так:

```cpp
#include "drevnerus_undo.hpp"
```

## Минимальные требования

- компилятор с поддержкой C++17;
- CMake 3.20 или новее; для явного генератора Visual Studio 2026 — 4.2+;
- исходники в UTF-8;
- для MSVC — ключ `/utf-8` (CMake-проект уже его задаёт).
